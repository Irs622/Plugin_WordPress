# Audit and remediation report: WP Knowledge Chat 0.1.0

**Date:** 2026-10-14 · **Branch:** `audit-remediation` · **Scope:** WordPress plugin, Node.js backend, knowledge base, evaluation, tests, documentation. Local verification only; nothing was deployed.

Every finding marked *Fixed* has a regression test that was run against the **original** code and failed there (or, for D1, hung), then passed after the fix. Test names are in the last column.

## Risks and observations (not code defects)

| ID | Area | Observation | Action |
|---|---|---|---|
| R1 | Scaling | Rate limits, daily budget and replay cache are in memory: single instance only. | Kept; documented as the supported mode with the trade-off ([deployment.md](deployment.md#scaling-decision)). No Redis added. |
| R2 | Origin check | `Origin` is not authentication; non-browser clients can omit it. | Documented; abuse bounded by rate limits and budget. No nonce added (would break LiteSpeed-cached pages). |
| R3 | Transients | WordPress rate-limit counters are not atomic; concurrent bursts can slightly exceed 6/min. | Documented; backend limits still apply. |
| R4 | Gate rules | Keyword rules (EN/ID) can be evaded by rephrasing; 6/22 held-out unanswerable questions still reach the model. | Documented; claim check is the backstop for numbers/contacts, not for invented prose. Live evaluation + owner review required. |
| R5 | Retries | One retry on 429/5xx/network errors may duplicate a provider call if the first one was processed. | Bounded to 2 attempts within the 12 s deadline; documented. |
| R6 | Compatibility | Declared ranges (WordPress ≥ 6.4, PHP ≥ 8.1) are checked statically (PHPCompatibilityWP 8.1+, APIs used exist since WP 6.3) but executed only on WordPress 7.1.3 / PHP 8.5.5. | Staging must cover PHP 8.5.11 + MySQL 8.0.46. |
| R7 | Content | Contact e-mail domain `inpartner.id` differs from the site; contact page has broken copy ("contact us (advisor) at for any inquiries"). | Flagged to the content owner; not changed. |

## Not changed, by decision

- Contact URL default stays `https://inpartnerglobal.com` (PRD §8.4). The admin help text no longer names `/contact/` as official; docs recommend it only after owner approval.
- Retrieval threshold `RETRIEVAL_MIN_SCORE` stays 1.0; evaluation thresholds unchanged (answerable ≥ 90%, now measured on the stricter "reaches the model with the right page").
- No WordPress nonce on the public chat endpoint (cached pages).
- No new runtime dependencies (backend still has zero).

## Blocked

| Item | Blocker |
|---|---|
| Real Gemini integration test, live evaluation, latency/failure rates with the real model | No `GEMINI_API_KEY` in the environment |
| MySQL 8.0, LiteSpeed/Apache, PHP 8.5.11, real devices and screen readers | No staging environment |
| Phone number, contact page, language scope, monthly budget, KB approval owner | Inpartner content owner / system administrator decisions |
