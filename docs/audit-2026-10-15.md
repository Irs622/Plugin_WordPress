## 1. Executive summary and release readiness

**Not ready for production. Ready for staging only after the content-owner decision in F1.**

- **F1, critical, blocked on the owner.** The current knowledge base (KB v2.0) does not match the pages it cites. On the live site, 0–8% of each document's lines can be found on its cited URL, and `https://inpartnerglobal.com/faq/` returns HTTP 404. The previous snapshot built from the site scores 100%. So every "grounded" answer links visitors to a page that does not say what the answer says. A new `npm run kb:verify-sources` command measures this. The content was not reverted, because choosing the source of truth is the owner's call.
- The new 0.2.0 features (leads, analytics, automatic sync) had several verified defects. Password-protected pages could be indexed. Any newly published page went into the AI knowledge base. Trashed pages were never removed. Spam submissions pushed real leads out of storage. Lead fields had no size limit. The widget showed server errors as success. Analytics stored personal data while the dashboard said it did not. All of these are fixed and have regression tests.
- KB v2.0 also quietly broke the offline answerability gate (design set 33/33 → 28/33 unanswerable stopped) without CI noticing. The gate is fixed, and CI now enforces it.
- **Live Gemini evaluation: not run.** A key file exists in the main checkout, but no budget was authorised. Commands are in §5.
- All local suites pass (§4). That is local evidence on SQLite and mock Gemini. It is **not** staging acceptance.

## 5. Evaluation

**Offline (deterministic, measured).** See §4. Dataset changes, all marked with a `note`:
- Six held-out items whose exact wording the rules were changed against (`h-u04`, `h-u08`, `h-u09`, `h-u11`, `h-u14`, `h-u20`) were **moved to the design set**. They no longer count as held out, so the held-out "18/18 stopped" is on the remaining 18 items only. **The held-out set needs fresh, unseen questions** before its numbers mean much again.
- `h-u05` and `h-u15` were stopped by correcting the evidence rules (F2), not by adding their phrases, so they stay held out.
- `uns-04` relabelled `either` (KB states 2009/2019).
- 17 new design items: false-refusal guards ("pricing terms", "structure agreements", "office in Jakarta" EN/ID), ID/KO variants of the new rules, link/WhatsApp elicitation, ID/EN prompt-extraction attempts, and four follow-ups with history.
- No threshold was lowered; `RETRIEVAL_MIN_SCORE` is unchanged (1.0).

**Live Gemini: NOT RUN.** A non-empty `GEMINI_API_KEY` exists in the main checkout's `backend/.env`, but no budget was authorised for this audit, so no provider calls were made and no live numbers exist. To run it on staging (needs the normal backend env):

```bash
cd backend
EVAL_COST_PER_1M_INPUT=<your rate> EVAL_COST_PER_1M_OUTPUT=<your rate> \
  node --env-file=.env dist/eval/run-eval.js --mode=live --max-model-calls=120
node --env-file=.env dist/eval/run-eval.js --mode=live --dataset=eval/holdout.json --max-model-calls=60
```

Each run reports: successful requests and failure rate, provider errors by kind, outcomes, answerable auto-pass (grounded, cites an expected page, no forbidden pattern), unanswerable refused / needs review, unsupported claims caught, valid source URLs, p50/p95 latency, tokens and estimated cost, and whether the call cap stopped the run. It writes `eval/report-live-*.json` with an empty `human_review` block per row.

**Human review (required before launch).** An Inpartner reviewer fills `human_review.verdict` for every row: `correct` (every statement is on the cited page), `unsupported_claim`, `wrong_refusal`, or `tone_language`. Grounded accuracy = `correct` ÷ answerable rows. Launch needs ≥ 90% and zero `unsupported_claim`. **Do not run this review until F1 is resolved.** Until then, "on the cited page" cannot be true for KB v2.0 content.

## 6. Security, lead privacy and knowledge-base sync

- **Lead access:** only `manage_options` users can see leads (admin screen). The post type has no UI, REST route, query var, search, export or core capabilities (an Editor cannot read or delete; tested). Anonymous visitors can submit only.
- **Abuse:** origin check, schema `maxLength`, honeypot, 3 per visitor per 10 min, 30 per site per hour, duplicate suppression, responses never echo submitted data, `Cache-Control: no-store`.
- **PII:** no IP stored; snippets redacted; the notification e-mail contains the lead (by design); the failure action carries no PII; backend logs unchanged (no message text).
- **Retention and deletion:** kept until deleted (default unchanged from 0.2.0 apart from the eviction bug). Per-lead or all delete, CSV export, WordPress privacy export/erase, optional `wp_knowledge_chat_lead_retention_days`. Uninstall deletes leads and metrics (documented in `readme.txt`).
- **Sync failure and rollback:** backend index updates are all-or-nothing and roll back on write failure (existing, verified by tests). On the plugin side, automatic updates are idempotent, computed from the page's current state, sent once per request at shutdown with a 10 s timeout, and recorded as pending with retries on failure. The Knowledge Base screen lists pending pages and has **Retry now**. `replace_all` still refuses to empty the knowledge base.

## 7. Remaining risks, owner decisions, deployment blockers

1. **F1 (blocker): choose the knowledge-base source of truth.** (a) Publish the KB v2.0 content on the cited pages (and a real FAQ page), then `npm run kb:build` and `kb:verify-sources`. (b) Revert `data/kb.json`/`sources.json` to the site-built snapshot (`git show b8875dc:backend/data/kb.json`) and re-label `h-u02`/`h-u03`/`faq-14`. (c) Cite a published company-profile page instead.
2. **Phone number:** the live contact page still shows three numbers, including a placeholder.
3. **Hosting:** single instance (supported) or serverless/multi-instance (needs shared rate-limit/replay/budget state, and KB updates by redeploy only).
4. **Budget:** sets `DAILY_REQUEST_LIMIT` and authorises the live evaluation.
5. **Lead policy:** retention period, privacy-policy wording, the widget's one-line privacy note (placeholder copy), notification recipient.
6. **Held-out set refresh** with new unseen questions; review `h-u02`.
7. Risks not fixed: keyword rules can be evaded by rephrasing; the name-claim heuristic may cause false refusals with the real model (unmeasured); the metrics counter and sync map use read-modify-write options (counts can be slightly low under concurrency); new admin strings are not yet translated into Indonesian or Korean; Elementor rendering of up to 200 pages on each Knowledge Base screen load can be slow on large sites; WP-Cron retries depend on site traffic (or a real cron).
